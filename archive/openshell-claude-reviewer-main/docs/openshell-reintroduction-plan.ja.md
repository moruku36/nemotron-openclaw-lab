# OpenShell 再導入の設計案

**状態：設計のみ。導入・設定変更・実機試験は未実施。**

## 目的と対象外

安定稼働している開発エージェントはそのままにし、成果物のレビュー **1 件だけ**を、使い捨ての OpenShell サンドボックスに分離できるか確かめる。本体の移行や、既存の承認・通知・定期ジョブ・推論経路の置き換えは対象外。既存経路で拒否された操作をこの仕組みで代行しない。

## 最初に試すこと

1. **試験先を分ける。** 既存サービスから分離できる Linux 環境を優先する。分離できない場合は使い捨ての別環境を選ぶ。採用する OpenShell の版とイメージを固定し、対応アーキテクチャ、カーネル、Landlock の強制適用を着手時に確認する。既存ホストのネットワークやコンテナ隔離を緩めない。
2. **ダミー差分だけを渡す。** 入力用ディレクトリを読み取り専用、専用の一時出力だけを書き込み可とする。初回は固定の模擬レビューを使い、外部通信・モデル呼び出し・既存の認証情報・ホストのホームやソケットの共有を許可しない。サンドボックスに GitHub の書き込み権限は与えない。
3. **有効な隔離を確認する。** ダミー差分を読めること、専用の出力だけを書けること、許可範囲外の無害な試験データにアクセスできないこと、外向き通信を許可しないことを確認する。期限で処理が停止し、破棄後の新規実行に前回の状態が残らないこと、既存の承認と定期処理に影響がないことも確認する。

## 合格条件と次の判断

- **合格**：上記をすべて記録できること。記録には版、実施した確認、期待値と実測、停止・破棄の結果だけを残す。認証情報や生ログは残さない。
- **停止**：隔離が強制できない、禁止操作が通る、期限後も処理が残る、または既存運用への影響を否定できない場合。試験環境だけを止め、既存経路はそのまま使う。権限を広げて再試行しない。
- **次段階**：合格し、別途承認が取れた場合に限り、非機密の実差分 1 件で既存レビューと指摘の品質・所要時間を比較する。実推論への接続は、送信先・入力範囲・認証・費用を確認してから。本体連携や NemoClaw への移行は別の判断とする。

## 既存検証との区別

[過去の検証記録](verification.md)では Apple Silicon 上で隔離確認が 13/13 通過しているが、ダミー認証情報での結果であり、実推論、非公開リポジトリを使うレビュー、開発エージェントとの一連の連携は未検証。今回の試験にその結果を流用しない。
